# 零基础三分钟上手（Windows）

> 这份文档写给**完全没装过 MCP 工具**的人。跟着做，不用懂原理。
> 每一步都有"怎么确认这步成功了"，卡在哪一步就停下看那一节的排查提示。
> 全部完成后，如果仍有问题，直接看 [FAQ-使用须知.md](FAQ-使用须知.md) 的「安装报错速查」一章。

---

## 第 0 步：先确认一件事

DoboCache 是一个**挂在 AI 客户端后面的小工具**，它本身没有界面、没有图标、不会出现在桌面。

装好之后你**看不到它**，你只会看到：AI 客户端里多了 9 个可调用的工具，以及（可选）对话末尾出现一张命中率报告卡片。

如果你期待的是一套能点开的软件，那它不是你想象的那样——这一点先说清楚，避免装完觉得"没反应"。

---

## 第 1 步：装 Node.js（约 1 分钟）

DoboCache 是用 Node.js 跑的。先检查你电脑上有没有。

按 `Win + R`，输入 `cmd`，回车，在黑窗口里粘贴这一行并回车：

```
node -v
```

| 你看到的结果 | 说明 | 下一步 |
|---|---|---|
| `v22.x.x` 或 `v20.x.x` 或 `v18.x.x` | 已装好，版本够 | 直接跳到第 2 步 |
| `v16.x.x` 或更低 | 版本太老 | 装新的（下面） |
| `'node' 不是内部或外部命令` | 没装 | 装（下面） |

**装 Node**：打开 <https://nodejs.org/zh-cn> ，下载标着 **LTS** 的那个（当前是 22.x），双击安装，**全程默认下一步**。

装完**必须关掉刚才那个黑窗口，重新开一个**，再执行一次 `node -v`，看到版本号才算成功。

> 为什么要求 18 以上：DoboCache 用到了一些新版本 Node 才有的 API，18 以下会直接启动失败。

---

## 第 2 步：下载并解压（约 30 秒）

1. 到发布页下载 `dobocache-v0.5.2-portable.zip`
2. 解压到**一个短路径**，建议就放在：

```
D:\dobocache
```

**三条要避开的坑**（这三条占了安装失败的一大半）：

- ❌ 别放在桌面或"下载"文件夹——路径太长，容易出问题
- ❌ 别放在 `C:\Program Files`——没有写权限
- ❌ 路径里别带中文、别带空格——很多工具解析不了

解压后，`D:\dobocache` 里应该能直接看到 `dist`、`src`、`README.md` 这些。**不要再多套一层文件夹**（比如 `D:\dobocache\dobocache-v0.5.2\dist` 就是多套了一层）。

**怎么确认这步成功了**：在黑窗口里粘贴下面这行（路径按你实际的改）：

```
node "D:\dobocache\dist\index.js"
```

- 如果窗口**卡住不动、没有任何报错** → ✅ 成功了。这是正常的（它在等客户端连接），按 `Ctrl + C` 退出即可
- 如果报 `Cannot find module` → 路径错了或多套了一层文件夹，回去看目录结构
- 如果报权限/被拦截 → 杀毒软件拦了，加个信任

> 这一步是整个安装里最关键的自检。**这一步能卡住不动，后面的配置就一定能成。**

---

## 分岔口：到这儿先选一条路（30 秒读完）

**第 1、2 步两条路都要做**（装 Node、解压）。从这一步开始分岔——**选一条就行，不要两条都装**。

| 你选的路 | 客户端需要满足 | 你要做的事 | 接着看 |
|---|---|---|---|
| **路线 A：本地代理**（推荐，最省事） | 只要能自定义 **baseURL**（接口地址） | 双击一个文件，把窗口里打印的地址填进客户端 | 下面「路线 A」三步，**第 3–6 步不用看** |
| **路线 B：MCP 挂载**（原有方式） | 客户端必须支持 MCP | 改客户端的 MCP 配置文件，把 `node dist/index.js` 挂进去 | 第 3 步往下，走完整六步 |

两条路共用同一套缓存内核、同一套日志、同一张体检卡，区别只是"谁来触发"。**路线 A 不用改任何配置文件**，所以对没配过 MCP 的人更友好。

---

## 路线 A：代理三步走（不改配置文件，约 3 分钟）

### A-1 启动代理

进到解压目录（例如 `D:\dobocache`），**双击 `start-dobostitch.cmd`**。

会弹出一个黑窗口，看到这样的内容就算起来了：

```
接入 baseURL 填：http://127.0.0.1:27880/anthropic（按厂商换前缀）
【DoboCache 体检卡 A】第 0 次请求 · 未知厂商
...
按 Ctrl+C 停止代理。
```

**怎么确认这步成功了**：窗口里出现上面那行「接入 baseURL 填：http://127.0.0.1:**27880**/...」。

**这个黑窗口不要关**，关掉代理就停了（可以最小化，不影响别的操作）。

### A-2 把地址填进客户端

打开你客户端里的「模型 / API 设置」那一页，找到 **baseURL（接口地址 / API Base）** 这一栏，把它改成窗口里打印的地址：

| 你用的厂商 | baseURL 填 |
|---|---|
| Anthropic（Claude 系） | `http://127.0.0.1:27880/anthropic` |
| OpenAI（及一切 OpenAI 兼容接口） | `http://127.0.0.1:27880/openai` |
| DeepSeek | `http://127.0.0.1:27880/deepseek` |

**密钥、模型名、请求内容一个字都不用改。** 改完照常提问即可。

**怎么确认这步成功了**：问第一句话之后，黑窗口会刷新成「体检卡 B」；**从第 2 轮请求起**卡上出现命中率百分比。第 0/1 次写「未判定（厂商未回传 usage）」是正常的，不是失败。

### A-3 想撤掉怎么办

把 baseURL 改回原来的地址，然后关掉那个黑窗口——就完全恢复原样。代理不改你任何系统设置，不写注册表，也没有后台常驻服务。

### 路线 A 的三条提醒

1. **端口被占用会自动顺延**（27880 → 27881 …），所以一律以窗口里**打印出来的那个地址**为准，别照抄本文档里的 27880。
2. 探活地址是 `http://127.0.0.1:27880/__dobostitch/health`，**不是** `/health`（后者返回 404，是正常的）。
3. 代理形态目前只在 **Windows 11 真机**验证过；Linux / macOS 上还没验证，装不上属正常，别硬试。

> 更细的可选参数（`--port` 换端口、`--rewrite` 改写档位、`--inject-usage` 补 usage、`--token` 本机校验）见包根目录 `README.md` 的「写法 D」一节。

## 第 3 步：找到你的客户端配置文件（约 30 秒）

不同客户端配置文件位置不同，找到对应那个：

| 客户端 | 配置文件位置 |
|---|---|
| **Claude Desktop** | `%APPDATA%\Claude\claude_desktop_config.json` |
| **Cursor** | 项目里的 `.cursor\mcp.json`，或全局 `%USERPROFILE%\.cursor\mcp.json` |
| **Cline**（VS Code 插件） | VS Code 设置里的 Cline → MCP Servers，或 `cline_mcp_settings.json` |
| **Windsurf** | `%USERPROFILE%\.codeium\windsurf\mcp_config.json` |
| **Continue** | `%USERPROFILE%\.continue\config.json` |

> 快捷打开方式：按 `Win + R`，把上面带 `%APPDATA%` 的那串整段粘进去回车，就能直接打开所在文件夹。

如果文件不存在，就**新建一个**。

---

## 第 4 步：粘配置（约 30 秒）

把下面这段整个复制进去。**只需要改一个地方：把路径换成你自己的**。

```json
{
  "mcpServers": {
    "dobocache": {
      "command": "node",
      "args": ["D:\\dobocache\\dist\\index.js"]
    }
  }
}
```

**三个必须注意的点**：

1. Windows 路径里的反斜杠要写**两个**：`D:\\dobocache` ，写成单个 `\` 会导致 JSON 解析失败
2. 如果你的客户端已经有 `mcpServers` 这一段了，**不要整个覆盖**——只把 `"dobocache": {...}` 这一块加进去
3. 改完存盘，注意别存成 `.txt`（记事本默认会加 `.txt` 后缀），文件名必须完全一致

**怎么确认这步成功了**：把整个文件内容复制到 <https://jsonlint.com> 校验一下，显示 Valid JSON 就对了。

---

## 第 5 步：完全退出并重启客户端（约 30 秒）

**这一步最容易做错**：不是关窗口，是要**真的退出进程**。

| 客户端 | 正确做法 |
|---|---|
| Claude Desktop | 右键任务栏图标 → Quit / 退出（右上角 X 只是最小化到托盘） |
| Cursor | 完全关闭后重新打开 |
| VS Code（Cline） | `Ctrl + Shift + P` → Reload Window |

重启后，在客户端的 MCP / 工具列表里应该能看到 `dobocache`，并且带 9 个工具。

---

## 第 6 步：说一句话验证（约 10 秒）

在对话里直接说：

```
用 dobocache 的 ping 工具检查一下
```

或者任何一句正常的话都行——它会自己在后台工作。

**看到这几种情况都算装好了**：

- 客户端工具列表里出现 `cf_` 开头的一堆工具 → ✅
- 让 AI 调 `ping`，返回正常状态 → ✅
- 对话末尾出现一张命中率卡片 → ✅（但默认是关的，见下）

---

## 第 7 步：判断你到底装成没成（对照表）

装完别靠感觉，对着下面这张表看一眼就知道。**左边是你实际看到的东西，右边是结论。**

| 你看到的 | 结论 | 下一步 |
|---|---|---|
| 工具列表里出现 `dobocache`，点开有 9 个工具（`ping`、`cf_judge`、`cf_tier`、`cf_inject`、`cf_meter`、`cf_warmup`、`cf_report`、`cf_prune`、`cf_normalize`） | ✅ **装成功了** | 不用再折腾，正常用 |
| 让 AI 调 `cf_report`，返回里有 `"version":"0.5.2"` | ✅ **版本对，跑起来了** | 同上 |
| 让 AI 调 `cf_report`，返回里有 `logDir` 和 `logDirSource` | ✅ **日志目录也通了** | 同上 |
| 配置写好了，但工具列表里就是没有 `dobocache` | ❌ 客户端没真正重启，或找不到 node | 速查**第 5 条**、**第 2 条** |
| 报 `spawn node ENOENT` | ❌ 客户端找不到 node | 速查**第 2 条** |
| 报 `Cannot find module ...` | ❌ 路径写错 / 多套了一层文件夹 | 速查**第 3 条** |
| 客户端启动直接报配置无效 / 工具列表整个空了 | ❌ JSON 语法错（多半是单反斜杠） | 速查**第 4 条** |
| 一切正常，但完全看不出任何变化 | ✅ **这是对的**，不是故障 | 继续看下一节 |

> 速查指 [FAQ 的「安装报错速查」](FAQ-使用须知.md#安装报错速查装不上先看这一章)。

### "跑起来了"具体长什么样

下面这段是本项目自动化校验脚本的真实输出（已脱敏），你可以拿它当参照 —— 你的客户端内部握手过程大致就是这些内容，能看到 `serverInfo.name = dobocache` 和版本号，就说明服务端正常应答了：

```
[握手] initialize / tools/list
  [PASS] serverInfo.name     = dobocache
  [PASS] serverInfo.version  = 0.5.2
  [PASS] protocolVersion     = 2024-11-05
  [PASS] tools/list 数量      = 9
  [PASS] 9 个工具齐全：ping, cf_judge, cf_tier, cf_inject, cf_meter,
                       cf_warmup, cf_report, cf_prune, cf_normalize

[工具调用] cf_judge（触发落盘）+ cf_report（读回日志目录）
  [PASS] cf_report.logDirSource = platform
  [PASS] cf_report.logDir       = C:\Users\<你的用户名>\AppData\Local\DoboCache\logs
  [PASS] 日志文件已写入：dobocache-2026-11-05.log.jsonl
```

> 客户端界面上通常看不到这些，它们发生在后台。你要确认的话，**直接让 AI 调 `cf_report`，把返回念给你听**就行 —— 这是最省事的验证方式。

## 装好了，但"看不出变化"是正常的

这是被问得最多的一件事，先说清楚：

**DoboCache 不改 AI 的回答内容，一个字都不改。** 它做的是让发出去的请求前缀更稳定，从而更容易命中服务商那边的缓存。

所以你的主观感受就是——**什么都没变，但账单变少了 / 响应快了一点**。这是设计如此，不是没生效。

想看到证据，有两个地方：

**① 打开白盒报告**（默认关闭）

对话里说一句：

```
把 dobocache 的白盒报告打开
```

下次请求完成后，对话末尾会多一张卡片，长这样：

```
[dobocache 白盒] reqIndex=7  hitRate=82.4%  prefixTokens=41230  cachedTokens=33970
                  prefixReady=true   minPrefixTokens=3450   mode=stable
```

- `hitRate` 是这一次请求的缓存命中率
- `prefixReady=true` 表示前缀已经稳定下来了
- 卡片默认关，是因为它会占用一点对话上下文，需要时开就行

**② 看日志**

日志在解压目录下的 `data\logs\`，每天一个文件。里面**不存你的提问原文**，只有长度、命中率这些数字。怎么读见 FAQ 第三章。

## 卡住了怎么办

按顺序自查，80% 的问题在这一步就能定位：

1. 黑窗口里手动跑 `node "D:\dobocache\dist\index.js"` —— **能不能卡住不动？**
   - 卡住 → 程序没问题，问题在客户端配置
   - 报错 → 按报错内容查 FAQ「安装报错速查」
2. 配置文件用 jsonlint 校验过没有？
3. 客户端是"关窗口"还是"真退出"？
4. 客户端工具列表里到底有没有 `dobocache`？

四条都过了还不行的，看 [FAQ-使用须知.md](FAQ-使用须知.md) 的「安装报错速查」——那里按报错原文逐条列了原因和解法。

---

## 一句话总结

> 装 Node → 解到 `D:\dobocache` → 配置文件里填 `node` + `D:\\dobocache\\dist\\index.js` → 真退出客户端 → 说句话验证。

看不到变化是正常的，要看证据就开白盒报告。
