# Code of Conduct

## Our commitment

This project is maintained by volunteers and used by people with very different
backgrounds and levels of experience. We want participation here — issues, pull
requests, discussions — to stay technical, respectful and free of harassment,
regardless of experience level, language, nationality, gender identity, or the
MCP client someone happens to be using.

## Expected behaviour

- Assume good faith and discuss the *problem*, not the person.
- Be patient with beginners. "It works on my machine" is not a diagnosis;
  neither is "read the docs" without a pointer to the part that was missed.
- Give reproducible detail when reporting: version, OS, Node.js version, MCP
  client, and the precise tool call that failed.
- Accept that maintainer time is limited. A "no" is normally about scope, not
  about you.

## Unacceptable behaviour

- Personal attacks, insults, or sustained dismissiveness.
- Harassment of any kind, including unwanted private contact, and publishing
  someone's personal information (real name, address, phone number, e-mail,
  account handles) without explicit permission.
- Posting other people's credentials, tokens, keys, customer data or production
  prompt content in issues, pull requests or logs.
- Deliberate disruption: spamming issues, reopening settled threads to argue,
  or submitting changes that intentionally degrade the project (backdoors,
  telemetry, undisclosed network calls, destructive file operations).
- Sexualised language or imagery, and any conduct that would be considered
  inappropriate in a professional setting.

## Scope

This code applies in all project spaces on GitHub (issues, pull requests,
discussions, commit comments, reviews) and whenever someone is representing the
project in public.

## Reporting

If you experience or witness unacceptable behaviour, contact the maintainers
**privately** — do not open a public issue naming individuals.

- Preferred: GitHub's *Report abuse* flow, or a private message to the
  maintainer account listed on the repository profile.
- If neither is available to you, open a public issue containing **only** the
  sentence "requesting a private channel regarding a conduct matter", with no
  names and no details; a private channel will be arranged.

No public e-mail address is published for this project, deliberately: a personal
mailbox is a single point of failure for spam, credential stuffing and
social-engineering attempts. Conduct reports are still welcome through the
channels above.

Reports are handled confidentially. The reporter's identity is not disclosed
without consent, except where required to act on the report.

## Enforcement

Maintainers will apply the response that fits the incident, in proportion:

1. **Correction** — a private note explaining what was inappropriate, with an
   expectation of changed behaviour.
2. **Warning** — a formal warning, with consequences for repetition.
3. **Temporary restriction** — temporary loss of the ability to interact in
   project spaces.
4. **Permanent removal** — permanent exclusion from project spaces, for severe
   or repeated violations.

Because this is a volunteer project, enforcement decisions are made by the
maintainers on a best-effort basis and are not subject to an appeals process.
Deliberately malicious code contributions are removed without prior notice.
